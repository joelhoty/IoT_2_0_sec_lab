課程大綱

第一篇：基礎原理與資安 41 頁

單元一：掃描之後發生什麼 第 1–8 頁

  1. QR Code 很方便，風險出在掃描之後的哪一步？
  2. IoT 與資安：本課程的兩個主題在架構中的位置
  3. QR Code 裡只有一段文字，動作由手機和網站決定
  4. 人看不出 QR Code 指向哪裡，張貼位置也不是證明
  5. 同樣是 QR Code，可能是網址、Wi-Fi、付款碼或登入碼
  6. 網址裡的亂碼字串，會讓手機中毒或直接下載嗎？
  7. HTTPS 的鎖頭證明了什麼，又不能證明什麼？
  8. 判斷：掃描、開啟、輸入、確認，是四個不同步驟

單元二：生活中的 QR Code 第 9–14 頁

  1. 點餐與菜單：公開資訊重在內容正確
  2. 付款碼與收款碼：誰出示、誰掃描、錢往哪裡？
  3. 掃碼登入：手機允許的是哪一台電腦登入？
  4. 三種常被混淆的 QR Code：直接寫網址、經過轉址、會一直更新
  5. 掃到的是哪一種？先看預覽網址的網域
  6. 複製一張 QR Code，和冒用它有什麼不同？

單元三：掃碼的人可能遇到的威脅 第 15–24 頁

  1. 先學會看網址：主機名稱與主要網域
  2. 案例一：繳費機上的 QR Code 被貼紙蓋住了
  3. 真實提醒：假繳費通知利用民眾原本的繳費需求
  4. 案例二：郵件裡的 QR Code，為什麼比連結更危險？
  5. 案例三：網址開頭像官網，為什麼還是假的？
  6. 案例四：掃描後被要求登入，帳密何時才外洩？
  7. 案例五：掃描後被要求安裝 App，何時才進入手機？
  8. 案例六：收款碼被換掉，顧客沒交出密碼也會受害
  9. 案例七：把付款碼截圖給別人，帳戶就可能被扣款
  10. 案例八：掃了別人傳來的登入碼，帳號被對方登入

單元四：發行 QR Code 的單位要面對的問題 第 25–29 頁

  1. 案例九：轉址設定被改或服務過期，印好的 QR Code 一起出錯
  2. 案例十：Wi-Fi QR Code 公開張貼，誰能取得什麼？
  3. 案例十一：點餐系統相信顧客改過的資料，帳就會算錯
  4. 先懂一件事：網頁會把某些文字當成「指令」
  5. 案例十二：簽到頁把 QR Code 裡的文字當成網頁程式碼執行

單元五：判斷與防護 第 30–40 頁

  1. 對照：掃不到或出現亂碼，先當成故障處理
  2. 對照：看不懂不等於保密，別把個資放進 QR Code
  3. 歸納：多數案例騙的是人，其餘是系統信錯了資料
  4. 外洩、被改、無法使用，分別損害哪一項安全目標？
  5. 如何辨識可疑的 QR Code？
  6. 預覽網址、官方 App、確認畫面，各擋住哪一段？
  7. 發行 QR Code 的單位，可以做什麼？
  8. 手機掃描設定：先顯示網址，再由你決定開啟
  9. 瀏覽器與 DNS：點開之後的第二道防線
  10. 判斷：網址看起來正確、也有鎖頭，就能輸入密碼嗎？
  11. 掃碼前先看網址，要求輸入或付款時先停一下

RFID／NFC

實作（36 頁）

課程大綱

第一篇：基礎原理與資安 30 頁

單元一：感應時發生什麼 第 1–8 頁

  1. RFID 與 NFC：靠近一下，系統做了哪些決定？
  2. 沒有電池的卡片，如何取得電力？
  3. 讀卡機與卡片如何來回傳送資料？
  4. RFID 有哪幾種？外觀相同的卡為什麼不能互用？
  5. 卡號、文字與金鑰：卡片裡的三種資料
  6. 認證：系統如何確認這張卡持有正確金鑰？
  7. 授權：通過認證後，為什麼仍可能被拒絕？
  8. 判斷：讀到資料、完成認證、使用服務，是三件事

單元二：生活中的 RFID 與 NFC 第 9–13 頁

  1. 設備與展品標籤：公開資訊重在內容正確
  2. 門禁卡：讀卡機、控制器、管理端各做什麼？
  3. 交通卡、信用卡與手機支付：讀到卡片資料就能交易嗎？
  4. 汽車鑰匙：靠近就解鎖的便利，換來什麼風險？
  5. 複製公開介紹，和冒用通行資格，有什麼不同？

單元三：標籤與資訊的威脅 第 14–15 頁

  1. 案例一：標籤被改寫或整張被換，訪客被帶到假網站
  2. 案例二：把管理密碼存進公開標籤，等於公告周知

單元四：門禁與通行的威脅 第 16–20 頁

  1. 案例三：門禁只查卡號，少了哪項驗證？
  2. 案例四：一組共用金鑰外洩，為什麼會影響多張卡？
  3. 案例五：卡片自己宣稱可到八樓，系統應該相信嗎？
  4. 案例六：讀卡機到控制器的線路被接上別的裝置
  5. 案例七：管理端已掛失，斷線的讀卡機還不知道

單元五：遠端轉送與支付 第 21–22 頁

  1. 案例八：昨天的成功回應，今天還能再用嗎？
  2. 案例八：卡片不在門邊，為什麼仍可能完成驗證？

單元六：判斷與防護 第 23–30 頁

  1. 對照：感應沒反應，先當成故障處理
  2. 對照：寫錯位置把卡鎖死，是操作失誤不是攻擊
  3. 外洩、被改、無法使用，分別損害哪一項安全目標？
  4. 認證、撤銷、通訊保護，各處理哪個問題？
  5. 掛失、換卡、換金鑰，為什麼不能互相代替？
  6. 使用者與管理者，各可以做什麼？
  7. 判斷：相同的文字加上正確的認證，夠開門嗎？
  8. 先問讀到什麼，再問系統相信什麼
